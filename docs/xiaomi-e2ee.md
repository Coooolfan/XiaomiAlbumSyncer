# 小米高级数据保护

支持在服务端解密并下载开启「高级数据保护」的小米普通相册图片和视频。录音沿用原下载通道。共享相册、云盘和远端缩略图解密暂不提供。

## 验证与下载

1. 在设置页添加小米账号，使用扫码登录或手动填写 userId、passToken。
2. 点击账号行的盾牌按钮，打开「小米高级数据保护」。
3. 点击「发送验证码」，从小米信任设备获取 6 位数字码并提交。
4. 显示「密钥已就绪」后，运行下载任务。

密钥在服务重启后仍可使用。同一 userId 更新 passToken 或再次扫码登录会保留已保存的密钥；更换账号 userId 会清除该行的 E2EE 凭据。删除账号会随账号凭据一起删除其密钥材料。

缺失文件所需密钥版本时，任务详情会提示需要验证，文件保持未完成状态。验证后可手动运行任务，或等待下一次调度重试。后台不会自动向手机推送验证码。发送验证码至少间隔 60 秒，服务端也可能施加额外限制。

验证码错误、过期、达到错误次数上限和登录失效均保留未完成的下载。已取得的 appkey 不会因为 serviceToken 失效而被清空。

## 密钥存储与备份

appkey 与信任设备 cookie 随账号的其他凭据一起保存在数据库 `credentials.xiaomiE2ee` 中。gallery appkey 按版本号保存，下载时精确匹配文件所需版本。验证码、临时 RSA 私钥、recordKey、encryptToken 和签名下载 URL 不会持久化，也不会通过账号 API 返回。

备份和迁移数据库即可保留已获取的密钥，无需额外配置密钥文件。数据库包含登录凭据和相册解密密钥，应限制数据库及备份的访问权限。

取 key 前会复用登录链路返回的会话 cookie，并调用 `/common/check` 补齐会话状态。keybag POST 表单附带 serviceToken；获取密钥的 POST 不自动重发，以避免重复消费 nonce 或验证码。

## 下载校验

图片、视频分别使用 `/gallery/image/storage` 和 `/gallery/video/storage`。是否解密依据文件级 `encryptInfo`，未开启保护或历史明文文件可使用同一接口下载；接口返回 `data.url` 时兼容原下载流程。

加密文件按块推进 AES-CTR counter，每块的起点为 `recordIV + blockIndex × 2^18`，不依赖所有非末块都恰好为 4 MiB。下载器流式写入临时文件，验证块明文 SHA-1、存在时的块密文 SHA-1、整文件明文 SHA-1 和大小后，才由流水线替换目标文件。这些分块校验不受任务「SHA-1 校验」开关影响。

单块失败最多尝试三次，并可使用响应中的备用 URL；重试会回退该块的临时输出。校验失败会删除临时文件。签名 URL 失效等无法恢复的下载失败由下一次任务重新获取 storage 元数据。

## 验证通知

验证提醒复用设置页的「账号认证失效通知模板」（`passTokenExpiredBody`），与小米登录失效、iCloud 重新验证共用，支持 `${account.nickname}`、`${account.userId}`、`${account.id}`。需要验证时，每个账号在当前服务进程内最多通知一次；验证成功后可再次通知。留空不发送此类通知。

## 开发验证

本地测试覆盖 keybag 的临时 RSA 握手、gallery 密钥分页、cookie 接续、WebCrypto/JVM AES-GCM 与 AES-CTR 互通、CRC32、counter 进位、明文兼容、损坏块重试、临时文件清理、密钥持久化及账号隔离。测试数据中的密钥均为合成数据。

协议与 HAR 证据见 [E2EE 调研](plan/e2ee/README.md)。真实小米账号联调需要在设置页主动发送验证码，完成一次取 key 和图片、视频下载后核对明文 SHA-1。
